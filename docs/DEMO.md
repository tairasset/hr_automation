# Демонстрация Resume Screener

## Подготовка

Установите приложение по [README](../README.md). Для демонстрации используйте [examples/candidates.csv](../examples/candidates.csv): обе записи вымышлены и не содержат контактов реальных людей. Запросы к Groq используют вашу квоту.

## Сценарий для заказчика

1. В CSV Dataset загрузите файл, выберите `name` как имя и `resume_text` как текст резюме.
2. Укажите должность Python Backend Developer, опыт 2 года и навыки Python, Django, SQL. Текстовый ввод дополнительных навыков доступен рядом с выбором.
3. В Advanced Settings задайте образование и веса. Оставьте сумму весов 100 и хотя бы один ненулевой вес. При закрытии расширенной секции используются значения по умолчанию — перепроверьте требования перед анализом.
4. Нажмите Analyze Resumes. Проверьте summary каждого кандидата: ошибки анализа нельзя интерпретировать как отказ.
5. Откройте Filter & Sort Results и сравните двух кандидатов. Объясните, что числа — ответы модели, а не измеренная вероятность успешного найма.
6. Откройте View Details, сгенерируйте вопросы и проверьте их соответствие исходному тексту.
7. Сгенерируйте черновик HR-письма, отредактируйте факты и формулировки. Отправки письма приложением нет.
8. Скачайте TXT и PDF; проверьте содержание и отображение символов.

Конкретные оценки и ранжирование не зафиксированы: ответы модели могут различаться.

## Проверка после установки

- Интерфейс открывается, без ключа появляется понятное сообщение при попытке анализа.
- С синтетическими данными API возвращает оценку и непустой summary.
- Сравнение, фильтры и переход к деталям работают.
- Генерация вопросов и письма, TXT/PDF-экспорт проверены вручную.
- Обновление страницы и New Analysis не используются как гарантия удаления персональных данных.

В репозитории есть три ручных API-скрипта в `resume_screener/_test_*.py`. Они обращаются к Groq, используют квоту и печатают ответы; `_test_parse_resume.py` также печатает фрагмент резюме. Это не изолированная автоматическая тестовая система. Не запускайте их на персональных данных в записываемом терминале.

## Скриншоты

Готовых скриншотов интерфейса в исходном дереве нет. После локального запуска можно сделать снимки рейтинга, сравнения и отчёта на синтетическом примере. Перед публикацией проверьте, что на снимках нет ключа, личных контактов, вкладок аккаунта или реальных резюме. Скриншоты не подменяются макетами.

## Статус проверки документации

Документация сопоставлена с исходниками; синтаксис app.py проверен через ast.parse на Python 3.14. Запуск приложения, установка его зависимостей и реальные API-вызовы в ходе оформления не выполнялись. Сценарий выше предназначен для последующей проверки, а не является отчётом об успешном тесте интерфейса.
