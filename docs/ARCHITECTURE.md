# Архитектура и карта исходников

## Текущая реализация

Приложение находится в одном [app.py](../resume_screener/app.py). Streamlit отвечает за формы, загрузки, рейтинг, сравнение и детали. `StoredFile` удерживает байты файлов в памяти сессии. `extract_text` обрабатывает PDF, DOCX, RTF и TXT, pandas читает CSV.

`build_job_description` собирает текст из формы. `analyze_resume` очищает и сокращает резюме, вызывает Groq и разбирает JSON. `_call_with_backoff` выполняет повторные попытки при rate limit; `_parse_analysis` ограничивает числовые диапазоны, но не обеспечивает полноценную валидацию схемы.

`generate_interview_questions` и `generate_hr_email` выполняют дополнительные вызовы Groq по запросу пользователя. `generate_pdf_report` формирует PDF через ReportLab. TXT собирается в странице деталей; данные выдаются кнопками скачивания.

## Данные и состояние

| Данные | Где обрабатываются |
| --- | --- |
| Исходные документы | Память серверной Streamlit-сессии; извлечение текста на сервере |
| Сокращённое резюме, имя и требования | Отправляются в Groq при анализе |
| Пробелы и фрагменты резюме | Отправляются в Groq при подготовке вопросов |
| Имя, должность и часть результата | Отправляются в Groq для черновика письма |
| Результаты, вопросы, черновики | Состояние сессии; постоянная база данных не реализована |
| TXT/PDF | Генерируются приложением и скачиваются пользователем |

Настройки хранения у провайдера не задаются этим кодом. Не следует обещать гарантированное удаление данных или изоляцию без отдельной проверки развёртывания.

## Файлы

- `resume_screener/requirements.txt` — зависимости с нижними границами версий, без lock-файла.
- `resume_screener/_test_groq.py` — ручная проверка ответа API.
- `resume_screener/_test_full.py` — ручная проверка JSON на демонстрационном тексте.
- `resume_screener/_test_parse_resume.py` — извлечение текста из PDF и запрос к API.
- `.devcontainer/devcontainer.json` — исходная конфигурация Codespaces с ограничениями, описанными в README.
- `.env.example` — имя переменной конфигурации, без ключа.
- `examples/candidates.csv` — синтетический ввод для демонстрации.

## Перед развитием продукта

Приоритетные технические задачи: отдельный статус ошибки вместо 0 / No Hire, сохранение контекста при повторных запросах, строгая проверка схемы и суммы оценок, уникальные идентификаторы кандидатов, экранирование текста при HTML/PDF-выводе, контроль доступа и определённый жизненный цикл данных. Это рекомендации по следующему этапу; в текущем портфолио они не заявляются как выполненные.
